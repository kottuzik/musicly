# תוכנית — Milestone 7: נוכחות, Audit והיסטוריית פעילות

> מקורות: `MILESTONES.md` (M7), `PRD.md` §3.1, §4.5 (ביטול בדיעבד), §4.7, §5.3; `ARCHITECTURE.md` §3.1–3.2, ADR-14; `DESIGN.md` §1.7–1.9, §1.12.
> עבודה מול Supabase **Development** בלבד. אין commit עד בקשה מפורשת.

## Context

M6 השלים את מחזור החיים של שיעור (שינוי, ביטול, שחזור) ופתח `audit_events` מינימלי (מבצע, ישות, פעולה, ערך קודם/חדש, בלי שמות). אבל אין עדיין דרך לדווח מה קרה בשיעור: האם התקיים, או מי לא הגיע. M7 מוסיף דיווח נוכחות, תיקון בכל עת, ביטול בדיעבד של שיעור שהתקיים (עם אזהרה), מסכי היסטוריה, וסיכומי Dashboard שסופרים רק שיעורים שבאמת התקיימו.

## 0. החלטות שהתקבלו בתכנון (ברירות מחדל שלי — אפשר לשנות לפני הבנייה)

1. **אין „ביטול דיווח”.** אפשר להחליף בין שלושת הסטטוסים ולערוך הערה, אבל לא לחזור למצב „לא דווח” (ה־PRD מדבר על הזנה ועדכון בלבד). טעות מתקנים בבחירת הסטטוס הנכון.
2. **דיווח נוכחות רק על שיעור במצב „מתוכנן”.** שיעור מבוטל או „יום סגירה” — אין נוכחות.
3. **Audit לא שומר טקסט חופשי.** הערות על תלמידים הן מידע אישי (ARCHITECTURE §5.3). ה־Audit שומר רק סטטוס קודם/חדש ודגל „יש הערה”; טקסט ההערה נשמר רק בטבלת הנוכחות.
4. **ביטול בדיעבד = מחיקת רשומת הנוכחות הנוכחית + רישום ב־Audit.** הנוכחות הקודמת נשמרת ב־Audit בלבד; השיעור לא נספר כשיעור שהתקיים. אחרי שחזור השיעור — המורה מדווח מחדש.
5. **מסך צפייה בפעילות למנהל:** עמוד אחד `/admin/activity` (מסנן תקופה וסוג, 50 בעמוד), נפתח מכרטיס בדף הבית — **בלי פריט חדש בתפריט** (DESIGN לא מגדיר פריט כזה).
6. **„ממתינים לדיווח נוכחות”:** רשימה קצרה בדף הבית של מנהל ושל מורה — שיעורים שנגמרו ב־30 הימים האחרונים בלי דיווח. בלעדיה אין דרך לגלות שיעורים שנשכחו. (אם לא רוצים — מוציאים.)
7. **הרשאות מורה:** רק מורה **פעיל**, רק בשיעורים שהוא המורה בפועל בהם (כולל מחליף). מורה לא פעיל — קריאה בלבד (היסטוריה אישית מלאה — M9).

## 1. הנחות מימוש

- שיעור שעתיד להתקיים אפשר לדווח עליו מראש (PRD). אין חסימת זמן.
- שיעורי עבר אינם ניתנים לשינוי מועד (M6), אבל נוכחות ניתנת לתיקון בכל עת, ואין הגבלת זמן.
- **שני מקבילים:** לרשומת נוכחות יש `version`. מורה ומנהל שמתקנים באותו רגע — השני מקבל `attendance_changed` ומרענן.
- **טריגר בטיחות:** כל מעבר של שיעור מ„מתוכנן” לכל מצב אחר (ביטול, יום סגירה) מוחק את רשומת הנוכחות ורושם ב־Audit — בשביל שהספירה לעולם לא תכלול שיעור שאינו מתקיים, גם בנתיבים מרובי שיעורים (הפסקת סדרה, השבתת תלמיד, יום סגירה).
- **אזהרה מפורשת** נדרשת רק בנתיבי ביטול שהמנהל מחליט עליהם לגבי שיעור בודד: ביטול ישיר ואישור בקשת ביטול של מורה. השרת מחזיר `held_confirmation_required` כשהשיעור מסומן „התקיים” והאישור לא נשלח.

## 2. Database — Migrations חדשים

קבצים (המשך לשרשרת הקיימת), שגיאות עסקיות ב־`P0001` עם מפתח יציב:

### 2.1 `20261104100000_attendance_schema.sql`
- טיפוס `attendance_status`: `held`, `student_absent`, `teacher_absent`.
- טבלת `attendance`: `lesson_id` (מפתח ראשי + FK ל־`lessons`, `on delete cascade`), `status`, `note` (עד 500 תווים), `reported_by`, `updated_by`, `created_at`, `updated_at`, `version`.
- RLS: `select` למנהלים, ולמורה על שיעורים שבהם הוא `teacher_id`; אין כתיבה ישירה. הוספה ל־Realtime.
- הרחבת בדיקת `audit_events.action` אם קיימת, והוספת אינדקס לקריאות לפי תקופה.

### 2.2 `20261104100100_attendance_functions.sql`
- **`set_attendance(p_lesson, p_status, p_note, p_version)`** — מנהל לכל שיעור; מורה פעיל רק בשיעורו. בודקת שהשיעור `scheduled` (`lesson_not_scheduled`), הרשאה (`not_allowed`), גרסה (`attendance_changed`), ויוצרת/מעדכנת. אם לא השתנה כלום — אין רישום. ל־Audit: `attendance_reported` / `attendance_changed`, עם `{status, has_note}` קודם וחדש, על ישות `lesson`.
- **טריגר** `lessons_status_attendance` (ראו §1) + פונקציית עזר פנימית שרושמת `attendance_cleared`.
- **עדכון `cancel_lesson` ו־`decide_lesson_change_request`**: פרמטר `p_confirm_held boolean default false`; ללא אישור על שיעור „התקיים” — `held_confirmation_required`. בעת הביטול נרשם ב־Audit `lesson_cancelled_after_held` עם הסטטוס הקודם.

### 2.3 `20261104100200_attendance_reads.sql`
- הרחבת `list_calendar_lessons` ו־`get_lesson` (drop + create, כמו ב־M6) עם `attendance_status`, `attendance_note`, `attendance_version`, `attendance_updated_by_name`, `attendance_updated_at`. מורה רואה רק את שיעוריו (כמו היום).
- **`list_history_lessons(p_student, p_teacher, p_from, p_to)`** — מנהל: כל השיעורים; מורה: מוגבל אוטומטית לשיעוריו. כולל מבוטלים (מסומנים), מורה בפועל, תחום, מיקום, נוכחות.
- **`list_unreported_lessons(p_limit)`** + ספירה — מנהל: כולם; מורה פעיל: שלו. שיעורים `scheduled` שנגמרו, ב־30 הימים האחרונים, בלי רשומת נוכחות.
- **`attendance_summary(p_from, p_to, p_teacher)`** — ספירות `held` / `student_absent` / `teacher_absent` / בלי דיווח, רק משיעורים `scheduled`.
- **`list_audit_events(p_from, p_to, p_kind, p_offset)`** — מנהלים בלבד; שמות נשלפים בזמן הקריאה (לא נשמרים ב־Audit). `p_kind`: הכול / נוכחות / שינויים וביטולים.
- הרחבת `list_recent_changes` (רשימת הפעולות) ו־`list_lesson_history` בפעולות החדשות.
- `revoke` מכולם ו־`grant` רק לפונקציות הפעולה והקריאה. אחרי כן: `npm run db:push`, `npm run db:types`, בדיקת advisors.

## 3. קוד אפליקציה

- **Lib:** `src/lib/lessons/actions.ts` (`setAttendance`, העברת `confirmHeld` לביטול ולהחלטה על בקשה), `queries.ts` (היסטוריה, לא־מדווחים, סיכום, פעילות), `labels.ts` (`ATTENDANCE_LABELS` + תוויות פעולות Audit חדשות), `validation/lessons.ts` (סכמת נוכחות), `errors.ts` (`attendance_changed`, `lesson_not_scheduled`, `held_confirmation_required`).
- **`LessonDetailsDialog`:** אזור „נוכחות” — שלוש אפשרויות (קבוצת רדיו נגישה) + הערה + שמירה; מי עדכן ומתי; לשיעור שאינו מתוכנן — מוסתר. במנהל: היסטוריית שינויים (כבר קיימת) מציגה גם את פעולות הנוכחות. ביטול של שיעור „התקיים”: חלון אזהרה עם „ביטול” / „בטל בכל זאת”.
- **לוח שנה:** תווית נוכחות קצרה על בלוק שיעור שדווח (לא ב־Month צפוף — שם נקודה צבעונית).
- **היסטוריית שיעורים (DESIGN §1.12):** לשונית „היסטוריית שיעורים” בפרטי תלמיד אצל מנהל, אצל מורה (`/teacher/students/[id]`, רק שיעוריו), ובפרטי מורה אצל מנהל (DESIGN §1.9). בחירת חודש, רשימת מפגשים עם תוויות סטטוס, כפתור „עדכון נוכחות” לפי הרשאה. רכיב משותף אחד.
- **`/admin/activity`:** טבלת Audit עם מסנני תקופה וסוג, מסך ריק, שגיאה וטעינה; קישור מכרטיס „שינויים וביטולים אחרונים”.
- **Dashboard:** מנהל — כרטיס „שיעורים שהתקיימו החודש”, רשימת „ממתינים לדיווח נוכחות (N)”; מורה — אותה רשימה אישית. `LiveRefresh` על טבלת הנוכחות.
- **נגישות/RTL:** תוויות סטטוס בטקסט (לא רק צבע), ניווט מקלדת בקבוצת הרדיו, תצוגה ב־Mobile/Tablet/Desktop.

## 4. בדיקות

- **Unit:** סכמת נוכחות (אורך הערה, סטטוס חוקי), תוויות, מיפוי שגיאות.
- **RLS / Database** (`tests/rls/attendance.test.ts`): מורה מדווח בשיעורו ולא בשיעור מורה אחר; מורה מחליף מדווח; מורה לא פעיל נחסם; כתיבה ישירה לטבלה נחסמת; גרסה ישנה → `attendance_changed`; שיעור מבוטל/יום סגירה נחסם; Audit בלי שמות ובלי טקסט הערה; ביטול של „התקיים” דורש אישור, מוחק נוכחות, שומר Audit; ביטול בסדרה/השבתת תלמיד מנקים אוטומטית; שחזור מחזיר שיעור ללא נוכחות; סיכומים לא סופרים מבוטלים; `list_history_lessons` מגביל מורה לשיעוריו. שיעורי עבר נוצרים בבדיקות ישירות דרך service role. ניקוי לפי `PREFIX`.
- **E2E** (`tests/e2e/attendance.spec.ts`): מורה מדווח „התקיים”, מנהל מתקן ל„התלמיד לא הגיע” ורואה היסטוריה; ביטול שיעור שהתקיים עם אזהרה; לשונית היסטוריה בתלמיד לפי חודש; דף הבית מתעדכן בלי רענון; מורה לא רואה תלמידים/שיעורים של אחרים. RTL, Mobile/Tablet/Desktop, מקלדת.
- **בסיום:** `npm run lint && npm run typecheck && npm test && npm run test:rls && npm run test:e2e` + `npm run build`.
